# План стабильной v1.5.0

Ручная проверка конвертации и четырёх размеров значка пройдена и утверждена
пользователем. Выпуск v1.5.0 разрешён 2026-09-27. Копия `LT My` остаётся
на beta для отдельной проверки реального обновления через UI после публикации.

## Общая настройка переключения системной раскладки

Статус: реализовано и проверено для стабильной v1.5.0.

- Заменить отдельную настройку Live на один общий переключатель на странице «Обзор».
  Он управляет переключением после успешного исправления в Live, Full и Majority.
  По умолчанию выключен.
- Сохранить поведение существующих конфигов: перенести значение
  `LiveSwitchInputLanguage` в новую общую настройку, не теряя ранее сделанный
  выбор пользователя. Обновить WebView2 и нативное окно настроек.
- Повторно использовать штатный запрос Windows с установленным RU/EN HKL,
  без эмуляции горячих клавиш. Проверять, что активное целевое окно не сменилось;
  отказ приложения переключить раскладку не отменяет успешную замену текста.
- Для Full и Majority запрашивать раскладку только после подтверждённой замены
  текста и только когда итоговое направление однозначно. Для смешанного текста,
  преобразованного в разные стороны, либо отсутствия изменений не угадывать
  направление и не переключать раскладку.
- Проверить оба направления для всех трёх режимов, выключенную настройку,
  отмену/ошибку замены, смену активного окна и неоднозначный смешанный текст.

Проверено синтетически для всех трёх режимов и на настоящем Windows Edit/HKL.
WebView2 и нативные настройки проверены; «Обзор» помещается без прокрутки
при стандартном размере окна. Ручная проверка конвертации пройдена пользователем.

## Безопасный updater, rollback и проверка запуска

Статус: реализовано и проверено для стабильной v1.5.0.

- Проверять размер и SHA-256 скачанного ZIP по внешнему `latest.json`.
- До замены файлов запускать отдельный `--health-check`: обязательные файлы,
  Full/Majority, Unicode и JSON. Не открывать UI и не изменять профиль.
- Не запускать старые релизы, не поддерживающие проверочный протокол,
  как будто они понимают `--health-check`.
- Подготовить новую копию на диске установки; `current → backup`, затем
  проверить готовность нового процесса и регистрацию горячих клавиш.
- Зафиксировать `install.json`, кэш runtime и автозагрузку только после
  успешного запуска. При сбое остановить только собственный новый процесс,
  вернуть старую папку и точные предыдущие метаданные/ярлыки.
- Удалять backup после успешного завершения. При неполном откате сохранить
  артефакты и показать их пути; ошибка уборки не отменяет рабочую установку.
- Для обновления из UI дождаться выхода старого PID; после безопасного отката
  запустить старую копию. Не завершать чужие процессы.
- Сохранить legacy migration, исправление Toolkir → Toolkit, выбор папки,
  явный `-InstallPath`, настройку автозагрузки и защиту Git/чужих папок.
- Разрешить обновление из UI для ручной копии без `install.json`: передавать
  установщику папку запущенной программы, после успешного обновления
  регистрировать её. Git-копии не обновлять этим механизмом.

Проверки: `Tests/Install.Tests.ps1`, `Tests/Install.Transaction.Tests.ps1`,
`Tests/HealthCheck.Tests.ps1`; реальные процессы AutoHotkey и временные
файловые установки на одном и разных дисках. Проверены ошибки startup,
assets/синтаксиса/хоткеев, таймауты и откат записанных метаданных.

Собран совместимый Windows ZIP с 38 файлами в `Layout Toolkit Ru En`,
проверен запуск из пакета, обновлён `latest.json` на стабильную v1.5.0.
Пройдены тесты Live, WebView2, lifecycle/prewarm, health/startup, legacy migration,
автозагрузки и transactional rollback, включая разные диски и Windows PowerShell 5.1.
Уже выпущенные beta не изменяются. Отдельная проверка реального обновления
через UI копии `LT My` запланирована после публикации; автоматически её не обновлять.
